# 测试

## 使用约定

本 Skill 独立安装和升级，方法、模板和参考 Schema 均在本目录。按当前任务读取必要资料；使用 PATH 中独立安装的 `swe-cli`，命令和覆盖边界见[CLI 约定](references/cli.md)。`contract.json` 只声明适用产物类型，不要求全部输入齐备，也不授权额外写入。

## 责任与范围

统一维护指定范围内的测试设计、单元测试、集成测试、端到端测试、替身、夹具、基准、测试快照和测试运行配置。业务模型、架构、接口契约、生产代码与部署配置只读；测试贴近源码放置也不改变所有权。共享配置仅修改已授权的测试条目。

测试环境的数据准备、隔离、故障注入、缓存与清理必须在明确运行范围内。生产缺陷和预期冲突记录依据与影响。不得修改生产代码增加测试钩子，或改业务预期让测试通过。已有单元测试也只能由本领域维护。

## 方法与依据

按[风险、测试与证据](references/method.md)确定观察目标，预期来自业务规则和已确认契约，不能从当前实现输出反向生成。现有代码用于了解接入方式，不代替正确性依据。可以在代码实现前设计测试，不要求先完成生产代码；缺少依据只阻塞相关场景。

测试设计、测试编写、执行和审查是本领域按任务选择的工作方式，不再拆为独立 Skill。小范围任务直接维护有效测试；需要长期测试设计时沿用[文档规则](references/document-format.md)与[模板](assets/test-design.md)，不为了流程完整制造文件。

## 检查与执行

维护测试设计时使用 `documents --kind test-design` 和 `artifacts --kind test`。风险标识唯一，显式场景引用采用 `场景:标识`，正文用三级标题定义；非法、重复或悬空引用需修正，自然语言关系人工核对。

测试代码运行项目已有测试工具，依据风险选择最小有效范围，再按必要性覆盖真实协作与端到端结果。YAML 项目的全部普通测试文件同样参与语言无关的结构归属检查；只有匹配语言适配器时才检查测试源码的导入关系。不能因测试方便绕过模块边界，也不能把没有适配器的语言依赖漏检说成通过。测试失败保留复现条件，区分生产、测试、设计与环境原因；只修复本领域产物。快照与预期变更需要独立业务或设计依据。

## 完成条件与只读模式

交付测试产物及命令、环境、观察结果、覆盖和未覆盖风险；绿色测试不能证明所有设计已兑现，失败也可形成有效的验证交付。仅要求审查时不写文件，不执行会落盘或修改业务数据的测试，明确哪些运行证据尚缺；修复在授权写入模式下完成，不启动额外工作流程。
