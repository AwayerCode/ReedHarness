# 更新与退出

## 更新

本 Skill 与 CLI 分别安装、更新和记录版本。插件管理的资源通过宿主更新，不直接覆盖宿主管理目录。DSH 退出插件时只关闭其拥有的服务，独立启动的服务由使用者管理；版本或工作区冲突应明确报告，不换端口掩盖冲突。

1. 记录本 Skill 来源与版本、CLI 版本和摘要、设计检查结果、项目指引及接线条目，识别本地修改。进行中的任务继续用原工具完成原基线检查；更新另建范围基线，不重建旧基线掩盖差异。
2. 在项目外保留待更新资源的完整副本。更新 CLI 时保留原二进制及版本摘要清单，验证其可执行性并保留至最终范围检查完成；更新本 Skill 时保留其文本与自有内容。
3. 更新本 Skill 时先校验独立文本包的发行摘要，解压到新的临时目录，比较候选内容，不先删除当前目录腾位置。CLI 从独立 `swe_<os>_<arch>.tar.gz` 获取，校验发行摘要后单独替换，并确认 PATH 指向预期版本。
4. 明确本地修改如何迁移，核对候选资源完整性后只替换选定资源。不能只覆盖新增文件而留下已删除的旧内容；不把旧摘要清单配给新二进制。资源不完整或自有修改尚未处理时不替换。
5. 用新 CLI 重新发现并执行适用的单份与批量检查，用原版本工具完成原基线检查。新增诊断区分规则变化、原有缺陷和迁移问题，不因升级放宽 YAML 或测试预期。接线仅修改授权条目。
6. 更新记录并完成验证后，核对临时目录绝对路径再清理。失败时保留恢复依据；恢复只涉及可确认属于本次更新的内容，不覆盖后续用户修改。

## 退出

退出项目先解除本次接入维护的引用，默认保留业务与设计数据。CLI 可能服务多个项目，不能因移除本 Skill 而顺带删除仍被使用的 CLI。

1. 检查真实消费者与当前配置，不只凭旧清单删除。保留原 CLI 的可执行副本至退出验证完成，建立包含接入记录与接线条目的范围基线。
2. 移除本次维护的 Hook、CI 或脚本调用和本 Skill 指引引用。共享文件逐条处理，保留其他检查、发布逻辑和用户修改；恢复旧值前确认当前值仍属于本次接线，不明确的条目标为待处理。
3. 默认保留 YAML、业务模型、代码、测试、部署资料及人工文档。保留的 HTML 标明历史视图。用户另行要求删除设计时须评估父级重新接管范围；本 Skill 不代为删除设计。没有剩余 YAML 时记录“无设计”，退出码 2 不能当作通过。
4. 核对本 Skill 安装目录的实际绝对路径、保留自有内容并确认不再引用后，移除其目录与专用忽略条目。CLI 仅在独立授权且确认所有消费者退出后移除。swe 没有卸载数据库，不调用不存在的卸载命令。
5. 检查残留调用，执行获授权的项目验证，更新退出记录；最后用保留的原 CLI 执行原基线 `scope check`。失败时报告并保留工具，不扩大基线或回滚用户修改。
6. 全部验证完成后核对路径并清理本次临时副本。项目外清理不受 Git 范围检查覆盖，需单独确认对象；退出不改写 Git 历史或回滚整个共享配置文件。
