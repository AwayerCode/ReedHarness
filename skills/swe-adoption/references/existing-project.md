# 项目发现与检查

## 发现与选择范围

读取项目指引、已有设计、构建配置、代码与测试，识别应用、语言、模块根和依赖关系。使用 PATH 中独立安装的 CLI 发现正式设计；`<项目根目录>` 是发现及批量检查的共同根，`<YAML路径>` 相对该根或为绝对路径：

```bash
swe version
swe system-design list --root <项目根目录>
swe system-design validate --root <项目根目录> --file <YAML路径>
swe system-design check --root <项目根目录> --file <YAML路径>
swe system-design validate --root <项目根目录> --all
swe system-design check --root <项目根目录> --all
```

`list` 不解析或校验内容，作用域存在不等于有效设计；无设计时据实记录。显式入口解析到真实目录，不通过符号链接制造第二个作用域。发现规则、父子隔离与输出见本地 [YAML 规范](system-design/guide.md)和 [CLI 约定](cli.md)。

每份 YAML 负责所在目录，源码范围由 `source_root` 限定。子 YAML 自动接管子目录，父级不能跨界声明或扫描；新增、移动、删除子设计都会改变父级覆盖。选择范围应体现真实职责，不能为隐藏违规切出子作用域。单份检查不代替受影响父子范围检查，批量通过也不能证明未纳入设计的目录合规。

## 设计依据与接入缺口

已有设计保持权威。代码和导入提供现状证据，不能直接转成允许依赖；结合业务意图区分应保留结构、实现偏差与未明确意图，循环或反向依赖不能因已经存在而获得许可。

缺少设计时，记录所需的源码根、层与模块职责、真实目录、必要文件及允许依赖等依据。目录归属须考虑启动组装、测试与生成文件；`required_files` 表达必须存在的文件，不是所有文件清单。当前结构无法表达时记录不支持或未覆盖范围，在有意义的边界内局部接入，不用虚构目录、空壳层级或放宽依赖伪造合规。本 Skill 不建立或重写这些设计，也不移动生产和测试文件。

已有设计校验失败时先保留结果：实现偏差保持预期；需求或责任变化记录设计修订依据；Schema 迁移记录不兼容字段与原有语义；意图不明或证据冲突标为待决。缺口只阻塞依赖它的接线，不能为 `check` 变绿重建 YAML。

## 接线与验证

正式文件名 `system-design.yaml` 即使内容无效也会建立边界。设计草稿不能提前落入父级受管目录遮蔽检查；CLI 不提供候选设计预演，对副本的检查不是真实仓库证据。接线引用已确认的正式设计与版本，不自动创建设计文件。

在授权的脚本、Hook 或 CI 配置条目中接入适用命令，保留原有检查、测试和发布语义。重新发现作用域，逐份完整 `validate`、`check`，必要时从包含受影响父级的共同根执行 `--all`；复核新增或消失的作用域及父级排除范围。仅层设计校验不代表完整设计或实现通过，批量失败须查看每份报告。

未内置适配器语言的实际依赖和不支持的 workspace 等限制按 CLI 覆盖报告；构建与测试仍用项目工具完成。失败时修复获授权的接线问题或记录未完成，不撤销用户变更或删除正式 YAML。只有适用的设计、实现检查与必要项目验证均完成，才能宣称对应范围接入验证完成；HTML 只是派生视图。
