# 项目接入

## 职责与改动范围

本 Skill 独立安装和升级，所有方法在自身目录。维护项目接入记录、必要的本 Skill 指引引用，以及独立 CLI 的检查入口接线。先确定目标目录、已有权威依据、可写文件或配置条目及验证范围；接入可以只覆盖一个应用，不等于接管整个 monorepo。

宿主已发现本 Skill 时不重复写入 Agent 指引。共享配置按条目编辑，保留已有内容和并行修改。业务模型、架构 YAML、生产代码、测试断言和发布策略作为接入依据，不因安装工具而获得修改权。需要改变这些产物时记录具体缺口与影响，不安排其他能力执行。

## 接入方法

首次接入读取[项目发现与检查](references/existing-project.md)，确认已有 YAML 的位置、有效性和受管范围，再接入检查命令。缺少设计时记录“无设计”及建立设计所需依据；不把当前代码或导入直接转成允许依赖，不通过重建 YAML 消除违规。

使用 PATH 中独立安装的 `swe`，工具定位、版本、命令及结果见[CLI 约定](references/cli.md)。CLI 检查已编码规则，项目工具验证行为；本 Skill 不提供设计生成器或候选设计预演。更新本 Skill、CLI 或退出项目时读取[更新与退出](references/lifecycle.md)，分别处理工具与项目产物生命周期。

## 完成证据

在项目现有约定位置保存最小接入记录：所选范围与未覆盖目录、YAML 位置、本 Skill 来源与版本、CLI 来源与版本、接线条目位置及用途、原有值与本次变化、验证结果和未验证项、退出时保留与移除的对象。使用项目相对路径，不保存凭据或个人机器路径，不复制架构正文或安装数据库。

分别报告工具已安装、设计已存在、设计检查、实现检查及行为验证的实际状态。失败或无法检查时保留准确结果，不将部分接入宣称为完成，也不通过放宽设计或删除用户文件消除失败。只读评估不修改接线或生成记录。

接入记录是供人阅读的项目记录，不对应 `swe` 可校验的产物类型；本 Skill 不声明 `contract.json`。
